# Project Overview

## What it is

Business Orbit — a community platform connecting college students with startup
founders/businesses. Marketing landing page + two application funnels (student,
business) + an admin dashboard to review/approve applications.

## Repo layout

```
businessorbitcommunity/
├── design_guidelines.json   # aspirational design spec written by the original AI
│                             builder (Emergent) — see design-system.md for how it
│                             diverges from what's actually implemented
├── frontend/                # Next.js 14 app (App Router), TypeScript
└── backend/                 # Express + TypeScript API, MongoDB via Mongoose
```

Single git commit, authored by `emergent-agent-e1 <github@emergent.sh>` — this was
generated by an AI app-builder platform, not hand-built incrementally. The `.next/`
build cache is (accidentally) committed. `backend/requirements.txt` is a **vestigial
FastAPI/Python dependency list — unused**; the real backend is 100% the Express/TS app
in `backend/src`. There are no `.py` files anywhere in the repo.

## Frontend

- **Next.js 14** App Router, **TypeScript** (`.tsx` — note `design_guidelines.json`
  says "jsx and js ONLY, do not use tsx"; the actual code ignores that and uses `.tsx`
  everywhere. Follow the code, not the JSON.)
- Styling: **Tailwind CSS**, custom tokens in `tailwind.config.js`
- Animation: **framer-motion** (fade/slide-up on scroll, staggered children)
- 3D: **react-three-fiber** + **three.js** — `components/InteractiveSphere.tsx`, a
  particle sphere that reacts to mouse position, reused as a background element on
  Hero, ProblemSection, `/student`, `/business`, `/orbit-card`, and `/orbit-card/checkout`
- Data fetching: **TanStack Query** (`@tanstack/react-query`) + **axios** client in
  `lib/api.ts`
- Icons: **lucide-react**

## Backend (`backend/src`)

Express + TypeScript, MongoDB via Mongoose, cookie-based JWT auth (access + refresh
tokens, httpOnly cookies).

- `server.ts` — app entry, mounts routes under `/api/{auth,student,business,admin}`,
  health check at `/api/health`
- `config/env.ts` — central env config, **exits the process if `JWT_SECRET` is unset**
- `models/` — `Student`, `Business`, `Admin`, `LoginAttempt` (Mongoose schemas)
- `modules/{auth,student,business,admin}/{controller,routes}.ts` — one folder per
  domain, each with its own controller + router
- `middleware/auth.ts` — reads `access_token` cookie (or `Authorization: Bearer`),
  verifies JWT, attaches `req.admin`
- `utils/email.ts` — SendGrid wrapper; **gracefully no-ops and logs to console if
  `SENDGRID_API_KEY` is unset** — no email actually sends in local dev unless you add a
  real key
- `utils/otp.ts`, `utils/jwt.ts`, `utils/password.ts` — small focused helpers

### API surface

```
POST /api/auth/login          { email, password } -> sets cookies, returns admin
POST /api/auth/logout

POST /api/student/apply       { name, college, course, email } -> creates pending Student
POST /api/student/send-otp    { email } -> generates + "sends" 6-digit OTP (10 min expiry)
POST /api/student/verify-otp  { email, otp } -> marks isEmailVerified
POST /api/student/submit-id   { email, idCardLink } -> saves ID link, sends welcome email

POST /api/business/apply      { name, company, role, stage, email } -> creates pending Business

GET   /api/admin/stats                       (auth required)
GET   /api/admin/students   ?status&search&page&limit
GET   /api/admin/business   ?status&search&page&limit
PATCH /api/admin/approve/:type/:id           type = 'student' | 'business'
PATCH /api/admin/reject/:type/:id
POST  /api/admin/bulk-email                  { recipients, subject, content }
```

### Data models

- **Student**: name, college, course, email (unique), otp/otpExpiry, isEmailVerified,
  idCardLink, status (`pending`/`approved`/`rejected`)
- **Business**: name, company, role, stage, email (unique), status
- **Admin**: name, email (unique), password (bcrypt hash), role
- **LoginAttempt**: brute-force lockout tracking (5 fails → 15 min lock), keyed by
  `${ip}:${email}`

Frontend's business form actually reuses the `role` field to hold a LinkedIn/website
URL (see the code comment in `app/business/page.tsx`) — the Mongoose field is named
`role` but the UI label is "LinkedIn / Website". Worth knowing if you touch that form.

### Auth flow

Admin login → bcrypt-verify password → issue `access_token` (15 min) + `refresh_token`
(7 day) as httpOnly cookies → `authMiddleware` on all `/api/admin/*` routes reads the
cookie and verifies. The admin user can be seeded manually using the `__helper/create_admin.ts` script, which creates the admin user from CLI arguments.
