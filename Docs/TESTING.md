# Business Orbit Community - Complete Testing Guide

This document provides exact, step-by-step instructions to verify the End-to-End integration between the Next.js frontend and the Express/Mongoose backend for all Business Orbit Community features. 

We test the exact lifecycle of a user from applying, getting approved by an admin, receiving an auto-generated password, logging into the community portal, updating their profile, ordering an Orbit Card via PhonePe, and the admin fulfilling that order.

## Prerequisites & Environment

Before testing, verify your backend `.env` contains:
```env
# MongoDB and Auth
MONGO_URL=mongodb://localhost:27017/business_orbit
JWT_SECRET=sandbox_jwt_secret

# Email (Resend)
RESEND_API_KEY=your_resend_api_key
EMAIL_FROM=your_verified_domain_email

# Cloudinary (Profile Photo Uploads)
CLOUDINARY_URL=cloudinary://API_KEY:API_SECRET@CLOUD_NAME

# PhonePe (Payments)
PHONEPE_ENV=SANDBOX
PHONEPE_MERCHANT_ID=sandbox_merchant_id
PHONEPE_SALT_KEY=sandbox_salt_key
PHONEPE_SALT_INDEX=1

*(Note: Inject real secrets securely through your local environment configuration. Exposed credentials must never be committed and should be rotated if exposed.)*
```

Start the application stack:
1. **Database:** Ensure MongoDB is running (`systemctl start mongod` or Docker equivalent).
2. **Backend:** `cd backend && npm run dev`
3. **Frontend:** `cd frontend && npm run dev`

---

## Phase 1: Admin Approval & Member Auto-Creation

When an admin approves a Student or Business application, the backend automatically provisions a `CommunityMember` account and emails them a securely hashed, autogenerated password.

**Test Steps:**
1. **Apply:** Go to `http://localhost:3000/apply/student`, fill the form, and submit.
2. **Admin Login:** Go to `http://localhost:3000/admin`, log in with `admin@businessorbit.in` / `admin123`.
3. **Approve:** In the dashboard under "Pending Applications", click **Approve** on the new student.
4. **Verification:** 
   - Use a disposable local fixture and controlled test inbox (or fixture) to verify password delivery. The new user should exist in the `communitymembers` collection with a `role` of `student` and a hashed password.

---

## Phase 2: Community Login & Profile Sync

Members use their email and the auto-generated password to access the exclusive community area.

**Test Steps:**
1. **Login:** Go to `http://localhost:3000/community/login`. Enter the approved user's email and the generated password from Phase 1.
2. **Authentication State:** You should be redirected to `http://localhost:3000/community`. 
3. **Session Verification:** Check your browser's Application tab (Cookies). You should see a `token` HTTP-only cookie.
4. **Directory Sync:** The community dashboard fetches `GET /api/community/members`. Verify that your newly approved profile appears in the community directory grid.

---

## Phase 3: Profile Updates (Self-Serve)

Members can update their bio, social links, and upload a profile photo via Cloudinary.

**Test Steps:**
1. **Update Text Fields:** In the community dashboard, locate the profile section. Modify the bio and LinkedIn fields and click save.
2. **Database Verification:** Check the `communitymembers` collection in MongoDB. The `bio` and `linkedin` fields should match your input.
3. **Photo Upload:** Upload an image in the profile section. 
4. **Cloudinary Verification:** The backend uses `multer-storage-cloudinary`. Go to your Cloudinary dashboard -> Media Library -> `business_orbit_profiles`. The image should be cropped to `400x400` and stored successfully. The frontend should display the new `photoUrl`.

---

## Phase 4: Orbit Card Payment Integration (PhonePe)

This tests the checkout flow. Use a PhonePe-supported sandbox or mocked payment provider by default. Do not use production credentials or real transactions for routine checkout tests. Production live-payment testing is moved to a separately approved runbook with explicit charge amounts and refund controls.

## Phase 5: Admin Order Fulfillment & Export

Admins need to download successful physical card orders to send to the printing and fulfillment center.

**Test Steps:**
1. **Admin Orders View:** Go to the Admin Dashboard (`http://localhost:3000/admin`). Navigate to the Orders section.
2. **List Orders:** The frontend calls `GET /api/admin/orders`. Verify that the successful Orbit Card order from Phase 4 is listed, populated with the member's name and company.
3. **CSV Export:** Click the **Export** button (`GET /api/admin/orders/export`).
4. **File Verification:** A file named `orbit-card-orders.csv` will download. Open it and ensure it correctly maps headers like `orderId`, `transactionId`, `memberName`, `shippingAddress`, and `amount` (formatted in INR, not paise).

## Automated Test Suites

To verify logic without manually running the UI, run the Jest suites. 
*Note: We test directly against a local MongoDB instance to perfectly mirror production behavior.*

```bash
cd backend
npx jest
```

**What the tests cover:**
- `community.test.ts`: Verifies paginated member fetching, auth blocks, profile text updates, and the exact SHA256 payload flow for PhonePe mock responses.
- `admin.test.ts`: Asserts that `json2csv` correctly flattens populated MongoDB documents and returns a `text/csv` buffer.
